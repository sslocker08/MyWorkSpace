# 人間必須 vs AIフルコミット自動 の境界 ＋ ツール内フィードバック仕様

## 境界（誰が何をやるか）
| 区分 | 例 |
|---|---|
| **人間必須**（AI代行不可・アカウント/法的責任/物理） | 法人/銀行/税(W-8/9)、Stripe/Apple($99/y)/Google($25)開発者・決済アカウントのKYC、独自ドメイン購入、コード署名/Notarization証明書、有料API/クラウド課金の与信、**価格と広告予算の最終承認**、商標/ブランド最終決定、App Store審査の提出と却下対応、返金/問合せ一次対応のエスカレーション、マーケットの内容モデレーション最終判断、**B2Bコンプラ系の専門家レビュー**（OSHA/医療/銃=有資格者）、**FAB物理検証**（実際にEVAを切って展開精度を確認＝メイカーのデザインパートナー）、実ユーザーインタビュー/プレイテスト募集 |
| **AIフルコミット自動**（人間ヘルプ最小） | 要件定義〜基本/詳細設計、実装、テスト/oracle、CI/CD・IaC、LP/SEO/コピー、**ビジュアル/デモ動画生成**、計測実装、`feedback`フォーム、エンジン/シミュレーションコード、adversarial review、ドキュメント、ローカライズ下書き |
| **協働**（AI主・人間が鍵を回す） | 決済/ストア/クラウド設定（AIが手順生成→人間がKYC/支払）、広告運用（AIがクリエイティブ/入札案→人間が予算承認/カード）、法務文書（AIがToS/Privacy/DPA草案→人間/弁護士が確認） |

> 運用: 各製品の「6リリース」前に **人間ゲート**（決済/ストア/法務/価格承認）を1つ置く。それ以外はAIで回す。

## ツール内「機能追加リクエストフォーム」`packages/feedback`（全製品標準搭載）
メールフォームではなく**ツール内**に置く（書き込みやすく、即反映できるため）。

### 要件
- ヘッダ/サイドバーに常設の「💡リクエスト」ボタン → モーダルの**インラインフォーム**（1クリックで開く・ログイン済みなら氏名自動）。
- 入力: 種別（要望/不具合/改善）＋自由記述＋任意スクショ＋**現在画面コンテキスト自動添付**（URL/機能ID/アプリ版）。
- 閲覧: 他者リクエスト一覧＋**投票(+1)**（公開ロードマップ）。重複は投票で集約。
- 書込先: 共有バックエンド（`feedback` テーブル）。**build-orchestrator の Phase1 入力に自動連携**（リクエスト→spec雛形を自動生成しトリアージ盤へ）＝「すぐ反映」を構造で担保。
- 計測KPI: リクエスト数 / 投票 / **反映リードタイム**（`retention-lifecycle`）。

### データモデル（最小）
```
FeedbackItem {
  id, productId, userId?, type: 'feature'|'bug'|'improvement',
  body, screenshotUrl?, context: { url, featureId?, appVersion },
  votes: number, status: 'new'|'triaged'|'planned'|'in_progress'|'shipped'|'declined',
  createdAt, updatedAt
}
```
