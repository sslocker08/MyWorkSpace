# 世界観監修チェックリスト ── 番人の手順

> ブランド戦略室が、各部署の発信・命名・製品コピー・コンセプトを**世界観（憲法）に照らす**ための共通手順。
> 語り口の基準は [tone_and_voice.md](tone_and_voice.md)、最終的なよりどころは [brand_concept.md](brand_concept.md)。

---

## いつ通すか（監修トリガー）

- 製品名・シリーズ名・キャッチコピーを新設／変更するとき
- SNS・PR・LP・商品ページなど**対外コピー**を出す前
- 次作（04/05ほか）の言語化・コンセプト確定のとき
- キャンペーン・コラボ・販路提案など、世界観に触れる施策のとき

---

## 第一関門：3つの問い（必須・1つでも欠けたら差し戻し）

[brand_concept.md](brand_concept.md) の判断基準。

1. **感覚を喚起しているか？** — 説明ではなく、感覚を呼び起こしているか。
2. **KIBIにしか言えないか？** — 一般論・他ブランドでも言える言葉になっていないか。
3. **急いでいないか？** — 焦り・煽り・トレンド便乗が滲んでいないか。

> 3問すべて ○ で初めて第二関門へ。1つでも △/✗ なら、その理由を添えて差し戻す。

---

## 第二関門：非交渉領域（全社共通の行動規範）

ひとつでも踏んでいたら世界観の毀損。该当箇所を指摘して修正を求める。

- [ ] **急がない**（「間」の哲学を壊していないか）
- [ ] **安売りしない**（値引き・煽り・希少性の過剰演出をしていないか）
- [ ] **香料スペックで押していない**（「○○を△%」式の説明になっていないか）
- [ ] **トレンド便乗で世界観を薄めていない**（流行の語感・ミームに寄っていないか）
- [ ] **個人名・私生活を過度に露出していない**（「ファウンダー」で統一されているか）

---

## 第三関門：声の質感（[tone_and_voice.md](tone_and_voice.md) と整合）

- [ ] 静けさと余白がある（言い切りすぎ・情報過多になっていない）
- [ ] 一人称・具体的な記憶から語られている（一般論の良い話になっていない）
- [ ] 写実の再現ではなく**翻訳**になっている（感情の核を差し出している）
- [ ] 製品の価値を軽くしていない

### 製品コピーの場合の追加確認

- [ ] 命名は命名哲学に沿う（状況・物の説明でなく、感覚の喚起）
- [ ] 三段構成（香りの説明 → 詩的キャプション → ブランド説明）に沿う
- [ ] 詩的キャプションに**香料名・処方詳細が出ていない**（対外非開示）

---

## 判定とハンドオフ

| 判定 | 意味 | 返し方 |
|---|---|---|
| ✅ 承認 | 3問○・非交渉領域クリア・声も整合 | そのまま進めてよい |
| 🟡 条件付き | 軸は合うが表現が薄い／説明寄り | 具体箇所を示し、書き換え案を添えて返す |
| 🔴 差し戻し | 3問の欠け・非交渉領域の抵触 | 抵触した原則と理由を明示して差し戻す |

差し戻し・条件付きのときは、**ダメ出しで終わらせず、世界観に沿った代替の言い方を1つ添える**のが番人の作法。

---

## 監修依頼の受け方（各部署 → ブランド戦略室）

世界観監修を全社の導線にするための受付手順。SNS・広報・営業資料・ECコピーなど、対外発信の前にこの導線を通す。

### 依頼する側（各部署）の手順

1. 自部署ステータス `../Secretary/status/<自部署>.md` の「他部署への依頼」表に1行追加する。
   - ID：`req-<自コード>-NNN`（例：マーケなら `req-mkt-001`）
   - 宛先：**ブランド戦略室（BRD）**
   - 内容：監修対象（コピー名・媒体・URLやパス）。**本文はコピペせずパス／IDで参照**する。
   - 緊急度・期限：必要なら記入。
2. `node ../Secretary/tools/build.js` を実行（依頼が `../Secretary/boards/requests.md` に集約され、BRDが読む）。

### 受ける側（ブランド戦略室）の手順

1. セッション開始時に build → `../Secretary/boards/requests.md` の**宛先BRDの行**を確認。
2. 対象に **本チェックリスト（第一〜第三関門）** を適用し、上の判定テンプレで `✅／🟡／🔴` を出す。
   - 差し戻し・条件付きのときは、必ず**世界観に沿った代替の言い方を1つ添える**。
3. 自部署ステータス `../Secretary/status/Strategy.md` の「受けた依頼への対応」表に、**依頼元と同じID**で行を追加し、ステータスを `回答済` にする。「回答・参照」列に判定（✅/🟡/🔴）と所見の置き場所を書く。
   - 所見が長いときは本文をここに書かず、`product_worldview/` か当該やり取り用メモへ書いてパス参照。
4. build を実行（集計が同IDで突き合わせ、依頼元に「回答済」が見える＝これが返信）。

### SLA（目安）

- **翌セッションまでに一次回答**（✅／🟡／🔴）。重い案件は受領→対応中→回答済の段階で進める。
- 命名・シリーズ名・ブランド根幹に触れる案件は、社長室エスカレーション基準に該当しうる。該当時は判断依頼 `jdg-brd-NNN` を起票し、その旨を回答に明記する。

## 使い方の例（テンプレ）

```
【世界観監修】対象：〈部署／コピー名〉
第一関門（3問）：① ○/△/✗  ② ○/△/✗  ③ ○/△/✗
第二関門（非交渉領域）：抵触の有無 →
第三関門（声）：所見 →
判定：✅／🟡／🔴
コメント：（抵触した原則・理由・代替の言い方）
```
