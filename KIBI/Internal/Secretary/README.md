# Shared ── 全社共有領域（本社直下）

全部署が読める・自分の持ち場にだけ書ける、会社の「現在状態」を置く場所。
チャットログではなく状態を管理する（AI会社の神経系）。2026-06-11 設置（dec-002）。

## 地図

| 場所 | 中身 | 書けるのは |
|---|---|---|
| `rules/` | 全社規程の正本（モデル規程・運用規程） | 社長室のみ |
| `templates/` | 各種様式（ステータス・タスク計画・成果物報告・日報） | 社長室のみ |
| `status/` | 部署別ステータス ×10 ＝**唯一の書き込み面** | **自部署のファイルのみ** |
| `boards/` | 全社ボード（tasks/requests/blockers/judgments/feedback/bulletin）＝生成物 | 手編集禁止（decisions.mdのみ社長室が記入） |
| `daily/` | 日報（朝礼統合・夕礼統合。1日1ファイル） | 社長室のみ |
| `dashboard/` | HTMLダッシュボード＝生成物 | 手編集禁止 |
| `archive/` | 完了行・過去日報の退避先 | 社長室（週次） |
| `tools/` | `build.js`（集計・生成）／`serve.js`（操作モード） | EC・情報システム部が保守 |

社長室専用コマンド：`/audit`（全社監査＝社長チェック。本体は `templates/audit-prompt.md`。`KIBI/.claude/commands/audit.md` 経由で社長室の席だけが使える）。

## 使い方（3手で回る）

1. **書く**：自部署の `status/<自部署>.md` を更新する（タスク・依頼・詰まり・判断依頼・アピール、すべてここ）。
2. **生成**：`node Internal/Secretary/tools/build.js` を実行する（部署フォルダからは `node ../Secretary/tools/build.js`）。
3. **読む**：`boards/` とダッシュボード（`dashboard/index.html`）で全社を見る。自分宛＝「宛先が自部署」の行。

## 鉄則（単一書き手原則）

- 1ファイル1書き手。**他部署のステータスファイルには絶対に書かない**。
- 依頼の往復は ID で連結する：依頼元が自分の「他部署への依頼」表に行を足し、宛先が自分の「受けた依頼への対応」表に同じ ID で状態を書く。
- ボードとダッシュボードは生成物。直したいときは元のステータスファイルを直して再生成する。
- 1つの事実は1箇所にだけ書く。ほかはパスと ID で参照する。

## 秘書室＝管制塔（拡大マンデート）

秘書室は共有領域の運用に加え、発注・審査の流れを途切れさせない管制塔を担う（職務定義＝`CLAUDE.md`）。

- **ord/tpr 監視**：`External/<vendor>/Orders/ord-###`・`ThirdParty/Cases/tpr-###` を巡回し、状態変化を拾う。
- **「誰の番か」追跡**：各案件の `OWNER`（社長室／Worker／Auditor／MAGI／Sota）を見て、ボールがどの席にあるかを可視化する。
- **タスク管理（tsk）**：全社の `tsk-###` を棚卸し・進捗追跡し、着手可能と滞留を仕分ける。
- **ボード/ダッシュボード維持**：生成物を最新に保つ（元ステータスを直して再生成）。
- **滞留検知**：規定時間を越えて同じ席で止まっている案件・タスクを検知し、進言する。

### 委任承認の範囲（自律境界）

正本＝`Contracts/automation-requirements.md`・`automation-design-draft.md` §10.5。

- **自室判断で推進可**：**Tier2 かつ軽微（`GATE:auto`）のみ**。Internal正本やTier1以上に触れない、機械的整理の範囲。
- **社長承認必須**：Tier0/Tier1・顧客接点・本番デプロイ・契約改訂・新規発注先の採用・支出。
- **エスカレーション**：External・ThirdParty からの進言・勧告は秘書室で止めず、社長へ上げる。
