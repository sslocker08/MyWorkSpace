# /check ── タスク一括消化（社長室・各部署 共通）

この席（部署）に溜まっているタスクを、丁寧に・並行で片付ける。スピードより確実さ。「急がない」哲学を守る。

## 0. 席の特定（どの部署か）
- 作業ディレクトリの `CLAUDE.md` 先頭を読んで判定する。
  - 「KIBI ── 社長室」で始まる → **社長室（HQ）**。共有領域への相対パスは `Secretary/...`、自部署ステータス＝`Secretary/status/HQ.md`。
  - 「KIBI ○○ ── 職務定義書」等 → **その部署**。共有領域への相対は `../Secretary/...`、自部署ステータス＝`../Secretary/status/<X>.md`（コード・編成表は当該 CLAUDE.md 記載）。
- 以降「自部署ステータス」＝この席のステータスファイル。**書けるのは自部署ステータスと自部署フォルダのみ**（単一書き手）。他部署フォルダ・他部署ステータス・boards へは書かない。
- 外注（External）・第三者審査（ThirdParty）・`Contracts/` への書き込みは社長室のみ（`../Contracts/master-agreement.md`）。

## 1. 棚卸し（build → 自分宛を読む）
- `build.js` を実行（社長室＝`node Secretary/tools/build.js`／部署＝`node ../Secretary/tools/build.js`）。
- 自部署ステータスと、boards の**自分宛**を読む：
  - 自部署タスク表（現役）。
  - 自分宛の依頼（`requests.md` で宛先=自部署。未受領/受領/対応中）。
  - 自分宛の社長フィードバック（`feedback.md`。差戻し/コメント/承認）。
  - 自部署の差戻し成果物（`review.md` でステータス=差戻し＝修正→再提出が必要）。
  - 自部署の詰まり(blk)・判断待ち(jdg)。
- （HQのみ）成果物が承認済になったHQタスクの締め候補も拾う。

## 2. 着手可能の抽出
**着手可能**＝次のもの：
- 未着手/進行中で、他部署待ち・社長室判断待ちでブロックされていないタスク。
- 自分宛の未対応の依頼（受領→対応）。
- 自分宛の**差戻し**（修正→再提出）・要対応の社長フィードバック。
**着手不可**＝外部待ち・他部署回答待ち・社長判断待ち・素材未支給のもの → 対象外。待ち理由を一覧化のみ。

## 3. 不足情報を先にまとめて確認（最重要）
- 着手可能タスクを精査し、**社長（あなた）の判断・追加情報・素材・方針**が要るものを洗い出す。
- それらを**一度に・箇条書きで**社長へ質問する（選択肢があるものは AskUserQuestion、自由記述は箇条書き）。タスクごとに小出しにしない。
- 回答を待つ間は、回答不要で進められるタスクの準備（調査・下書き）だけ進めてよい。
- 世界観・価格・対外発信・法務・個人情報・決済・**外部AIへの情報共有**に踏み込む判断は、確認なしで進めない。

## 4. 並行処理（成果物づくり）
- 着手可能タスクを**並行**で処理する。タスクごとに編成表のモデルで担当を割り当て、複数あれば **Agent を並行起動（1タスク1エージェント）**。
- **各エージェントの鉄則**：成果物は**自部署フォルダ内にタスクごと別ファイル**で作る（衝突回避）。**自部署ステータスへは書かない／`build` も実行しない**（単一書き手・build競合の回避＝取りまとめはこの席が最後に一度だけ行う）。
- 物理作業・外部送信・公開・本番反映・DM送信・アカウント操作は**自走させない**（ドラフトまで）。
- 各成果物は編成表のレビュー担当の観点でセルフレビュー。世界観に触れるものはブランド戦略室（Strategy）へ `req` で監修依頼。
- **複数部署が絡むタスクは分解する**（coordination-spec §6）：起票部署が**社内便（送信）**でスレッドを立て、宛先部署へ段階的に申し送り/依頼する。前段の宛先が回答済になってから次段、並行可能なら同時に複数宛先へ。スレッドは `スレッド` 列でタスク/reqに束ね、**タスクがクローズするまで往復を継続**（返信も自部署の送信行に同スレIDで書く）。連携タブにスレッドとして表示される。

## 5. 取りまとめ（この席だけが書く）
- 各エージェントの結果を集約し、**自部署ステータスを一度だけ更新**：
  - タスクの進捗/ステータス（小・中で自部署内に閉じるもの＝完了化可／**大・特大・対外・部長判断で重要＝完了化せず**）。
  - **成果物（レビュー用）表**へ追加：大・特大・対外・重要は「レビュー=社長・ステータス=レビュー待ち・パスはKIBIルート相対・提出日=本日」（社長承認まで完了化しない＝レビュー関門 `rules/review-gate.md`）。
  - 受けた依頼への対応（受領→対応中/回答済）、起票した依頼（`req-<自コード>-NNN`）、夕礼欄、共有・アピール。
  - （HQのみ）成果物が全て承認済のHQタスクは「完了」＋完了日に締める。
- `build.js` を**一度**実行（最後にこの席だけが回す）。**関門違反警告**が出ないことを確認。

## 6. 報告（簡潔体）
- 着手したタスク・成果物パス・レビュー提出分・起票した依頼・（未回答があれば）社長への質問・着手不可の待ち一覧。

$ARGUMENTS があれば対象の絞り込み（例「依頼だけ」「差戻しだけ」「tsk-mkt-005」「最高優先だけ」）として解釈する。
